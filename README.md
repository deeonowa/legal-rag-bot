# Legal RAG Bot — Юридический AI-ассистент

Локальная RAG-система (Retrieval-Augmented Generation) для работы с юридическими документами через Telegram-бота. 

## Возможности

- **Локальная работа** — все данные остаются на вашем компьютере
- **Telegram-бот** — удобный интерфейс для вопросов
- **Гибридный поиск** — BM25 + векторный поиск для максимальной точности
- **Поддержка PDF, TXT, MD** — загрузка документов разных форматов
- **Автоматическое кэширование** — быстрая работа после первой индексации
- **Источники ответов** — показывает, из каких документов взята информация

## Требования

- **Python 3.10** или выше
- **[Ollama](https://ollama.com/)** (установите с официального сайта)
- **Telegram-аккаунт** (для получения токена бота у [@BotFather](https://t.me/BotFather))

## Установка и запуск

### Шаг 1: Клонирование и виртуальное окружение

```bash
# Клонируйте репозиторий
git clone https://github.com/deeonowa/legal-rag-bot.git
cd legal-rag-bot

# Создайте и активируйте виртуальное окружение
# Для Windows:
python -m venv rag_env
rag_env\Scripts\activate

# Для macOS/Linux:
python3 -m venv rag_env
source rag_env/bin/activate
```

### Шаг 2: Установка зависимостей

```bash
pip install -r requirements.txt
```

### Шаг 3: Настройка Ollama

Убедитесь, что Ollama запущена и скачайте необходимые модели:
```bash
ollama pull qwen3.5:9b
ollama pull bge-m3
```

### Шаг 4: Настройка переменных окружения

Скопируйте шаблон файла настроек:
```bash
# Windows
copy .env.example .env
   
# macOS/Linux
cp .env.example .env
```

Откройте файл .env в любом текстовом редакторе и вставьте ваш токен:
```bash
# Получите токен у @BotFather в Telegram, отправив команду /newbot
TELEGRAM_BOT_TOKEN=ваш_токен_от_BotFather
```

### Шаг 5: Загрузка документов

Поместите ваши юридические документы (.txt, .md, .pdf) в папку my_docs/ (Предварительно папку необходимо создать)
Выполните скрипт индексации:
```bash
python populate_db.py
```

### Шаг 6: Запуск
Вариант А: Telegram-бот (Рекомендуется)
```bash
python bot.py
```

Вариант Б: Консольный режим (Для тестов)
```bash
python main.py
```

## Конфигурация

Для работы системы необходимо создать файл .env на основе .env.example. Ниже приведено описание всех доступных параметров:

| Переменная | Значение по умолчанию | Описание |
|------------|----------------------|----------|
| `TELEGRAM_BOT_TOKEN` | *(обязательно)* | Токен вашего бота, полученный от [@BotFather](https://t.me/BotFather) в Telegram. |
| `EMBEDDING_MODEL` | `bge-m3` | Модель для создания векторных представлений текста. Рекомендуется `bge-m3` для лучшего понимания русского языка. |
| `LLM_MODEL` | `qwen3.5:9b` | Основная языковая модель (через Ollama), которая генерирует итоговый ответ. |
| `DB_PATH` | `documents.db` | Путь к файлу базы данных SQLite, где хранятся метаданные документов. |
| `CHROMA_PERSIST_DIR` | `./chroma_db` | Директория, в которой сохраняются векторные эмбеддинги для быстрого поиска. |
| `DOCS_FOLDER` | `./my_docs` | Путь к папке, из которой скрипт `populate_db.py` считывает файлы. |
| `CHUNK_SIZE` | `1000` | Размер текстового фрагмента (в символах) при разбиении документов. Оптимально для юридических текстов. |
| `CHUNK_OVERLAP` | `200` | Количество символов перекрытия между соседними фрагментами для сохранения контекста. |
| `RETRIEVER_K` | `5` | Количество наиболее релевантных фрагментов, которые передаются модели для формирования ответа. |

## Использование бота

После запуска скрипта `python bot.py` вы можете взаимодействовать с ассистентом прямо в Telegram.

### Доступные команды
- `/start` — Приветственное сообщение и краткое руководство.
- `/help` — Подробная справка о возможностях системы и примерах запросов.
- `/stats` — Показывает текущую статистику: количество загруженных документов и векторных фрагментов (чанков).
- `/rebuild` — **Важно:** используйте эту команду после добавления новых файлов в папку `my_docs/` и выполнения `python populate_db.py`, чтобы обновить поисковый индекс.

### Как задавать вопросы
Просто напишите свой вопрос в чат как обычное сообщение. Система автоматически найдет релевантную информацию в загруженных документах и сформирует ответ с указанием источников.

**Примеры эффективных запросов:**
- «Какой срок уведомления Роскомнадзора об утечке персональных данных?»
- «В каких случаях обработка данных возможна без согласия субъекта?»
- «Что будет, если субъект КИИ не проведет категорирование своих систем?»
- «Какая команда используется для шифрования диска в NebulaOS?»
- «Перечисли коды ошибок NebulaNet и их расшифровку.»

## Решение частых проблем

**1. Ошибка `ConnectTimeout` или `Timed out` при запуске бота**
- **Причина:** Ваш интернет-провайдер блокирует или сильно замедляет доступ к серверам Telegram (`api.telegram.org`).
- **Решение:** Включите VPN на компьютере. Если вы используете локальный прокси-клиент, добавьте его настройку в `bot.py` при инициализации `Application` (параметр `request=HTTPXRequest(proxy="http://127.0.0.1:ВАШ_ПОРТ")`).

**2. Ошибка `Connection refused` от Ollama**
- **Причина:** Фоновая служба Ollama зависла, завершила работу или не была запущена.
- **Решение:**
  1. Закройте Ollama через системный трей (правая кнопка мыши → Quit Ollama).
  2. Убедитесь в Диспетчере задач, что процессы `ollama.exe` полностью завершены.
  3. Запустите Ollama заново из меню Пуск.
  4. Проверьте статус командой в терминале: `ollama ps`.

**3. Бот отвечает: "В предоставленных документах нет информации", хотя вы знаете, что она там есть**
- **Причина:** Векторный индекс устарел, не был создан, или документы не попали в базу данных.
- **Решение:**
  1. Убедитесь, что нужный файл физически находится в папке `my_docs/`.
  2. Выполните в терминале команду: `python populate_db.py` и дождитесь сообщения об успешном добавлении.
  3. Отправьте боту в Telegram команду `/rebuild` и дождитесь завершения обновления индекса.

**4. Генерация ответа занимает слишком много времени**
- **Причина:** Локальная языковая модель работает на центральном процессоре (CPU), а объем передаваемого контекста слишком велик.
- **Решение:** Откройте файл `.env` и оптимизируйте параметры:
  - Уменьшите `CHUNK_SIZE` до 500 или 600.
  - Уменьшите `RETRIEVER_K` до 3.
  - Попробуйте использовать более легкую модель в `LLM_MODEL` (например, `qwen3.5:7b` или `qwen3.5:3b`), если точность позволяет.
